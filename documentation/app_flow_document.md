# AI-LMS Portal App Flow

## Onboarding and Sign-In/Sign-Up

When a new user arrives at the AI-LMS Portal, they land on a simple welcome page that invites them to sign in with Google. This page displays the portal logo, a brief introduction, and a prominent “Sign in with Google” button. Clicking that button sends the user to Google’s secure login prompt. After the user enters their Google credentials, the portal uses NextAuth.js to verify the user’s identity and then checks the user’s email against a list of defined roles. If the email belongs to an administrator, the user is tagged as IT_ADMIN. If it belongs to a teacher address, they become GURU. Otherwise, they become SISWA (student). When authentication completes, the portal redirects the user to their role-specific landing page. Signing out is done with a single “Logout” link in the header. This link ends the user session and sends them back to the welcome page. Because authentication uses Google, password recovery is handled directly by Google’s account settings, so no separate forgot-password page is needed in the portal.

## Main Dashboard or Home Page

After signing in, the user arrives at a home page tailored to their role. The page layout is consistent across roles, with a top header bar, a collapsible sidebar on the left, and the main content area in the center. The header shows the portal name on the left and a profile avatar on the right. Clicking the avatar opens a dropdown for account details and the logout link. The sidebar lists navigation links that change based on the user’s role. Teachers see links to “Dashboard” and “Materials.” Students see a link to “My Feedback.” Administrators see “Admin Settings.” The main content area shows either an overview dashboard (for teachers), a feedback history (for students), or configuration options (for administrators). From here, users click navigation links or action buttons to move to other parts of the app.

## Detailed Feature Flows and Page Transitions

When a teacher clicks the “Dashboard” link in the sidebar, the app transitions to a page that displays class statistics, charts, and data tables. The page component fetches live data with React Query calls to the Google Apps Script backend. Once the data loads, interactive charts render with the ChartArea component, and a DataTable lists performance metrics. A “Print Report” button at the top triggers a print stylesheet and calls `window.print()` so the teacher can produce a paper report. 

From the dashboard, the teacher can navigate to “Materials.” On that page, the teacher finds a form for uploading new lesson files. They click an “Upload File” button to open a file picker, select a PDF or image, and then fill in a title and description. When they submit, the file is converted to Base64 and sent via a POST request to the GAS endpoint. The page shows a loading spinner while the upload happens. Once it succeeds, a success message appears and the new material shows up in the materials list. Each material entry has an “Edit” button that opens a modal with input fields pre-filled. The teacher can change the title or description, save changes, or delete the entry. After any change, the list refreshes with the updated data.

When a student clicks “My Feedback,” they see a table of feedback entries that the teacher has left. Each row shows the date, subject, and feedback text. The student can click a row to expand it and read longer comments. All data is fetched on page load with React Query from the GAS API. If there is no feedback yet, a friendly message invites the student to check back later.

When an administrator clicks “Admin Settings” in the sidebar, they arrive at a page with forms for global portal configuration. This includes fields for school name, session calendar, and allowed file types. The admin updates values and clicks “Save Settings.” The portal sends the new settings via a POST request to the GAS endpoint. A confirmation banner appears when the save succeeds. From this page, the admin can also manage user roles by entering an email address and selecting a role from a dropdown. After saving, the new user is immediately able to sign in with their assigned role.

## Settings and Account Management

Every user can click on their avatar in the header to view account information. This page displays the user’s name, email, and assigned role. Although profile editing is minimal, admins can adjust roles here if they have permission. There is also a toggle switch for light or dark mode that saves a preference in local storage. Notifications preferences appear as simple on/off switches. Saving these preferences triggers an API call to store settings in the backend. After any changes, the user clicks “Back to Dashboard” or selects another link in the sidebar to continue using the portal.

## Error States and Alternate Paths

If a user tries to reach a page they are not allowed to view, the app immediately redirects them to a 403 error screen with a message stating they do not have permission. If their session expires or they attempt an action without being logged in, they return to the welcome page. During API calls, if the network is down or the GAS endpoint returns an error, the page shows a toast notification saying “Unable to load data. Please try again.” Forms that fail validation, such as uploading an unsupported file type, display inline error text next to the field. The user can correct the input and retry. When connectivity is restored after a failure, the app automatically retries pending queries or offers a manual “Retry” button.

## Conclusion and Overall App Journey

In summary, a user starts on the simple landing page and chooses to sign in with Google. NextAuth.js authenticates them, assigns a role, and redirects them to the appropriate home page. Teachers explore their dashboard, print reports, and upload materials. Students check their feedback history in a clean table view. Administrators manage global settings and user roles. All navigation happens through a consistent header and sidebar layout. Error messages guide the user through invalid inputs or permission blocks. Preferences and account settings stay easy to find under the profile avatar. This flow ensures that from the moment a user signs in to their routine interactions—whether viewing charts, uploading files, or managing settings—they have a clear, guided path through the AI-LMS Portal.
